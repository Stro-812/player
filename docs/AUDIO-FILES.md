# MP3 подкаста «Не про бег» на сервере

Инструкция для тех, кто выкладывает аудиофайлы. Сайт-плеер — статический: страница
в браузере сама запрашивает MP3 по прямой ссылке и играет его обычным элементом `<audio>`.
Серверного кода и базы данных нет.

## Коротко

1. Переименовать 11 файлов в `01.mp3` … `11.mp3`.
2. Положить их в папку `/audio/` на том же домене, где будет сайт:
   `https://<домен>/audio/01.mp3` … `https://<домен>/audio/11.mp3`.
3. Убедиться, что сервер отвечает **206 Partial Content** на запросы с заголовком `Range`.
4. Прислать вывод команды из раздела «Что прислать обратно».

## 1. Имена файлов

Переименовать **обязательно**. Сайт ищет файлы по точным именам: две цифры номера эпизода
и `.mp3`, латиница, нижний регистр, без пробелов.

| Эпизод | Имя на сервере |
| --- | --- |
| 1 | `01.mp3` |
| 2 | `02.mp3` |
| … | … |
| 10 | `10.mp3` |
| 11 | `11.mp3` |

Если исходные файлы называются «Эпизод 1. Марафон и поэты.mp3» и т. п. (номер — первое
число в имени), копии с нужными именами можно сделать так. Исходники не трогаются:

```sh
mkdir -p audio
for f in *.mp3; do
  n=$(basename "$f" | grep -oE '[0-9]+' | head -1)
  cp "$f" "audio/$(printf '%02d' "$((10#$n))").mp3"
done
ls audio        # должно быть 01.mp3 … 11.mp3
```

Перекодировать и менять теги не нужно, файлы кладутся как есть.

## 2. Куда положить

Папка `/audio/` в корне того же домена, где будет лежать сайт. Тогда сайт находит файлы сам
и настраивать ничего не нужно.

Если файлы будут на другом домене или в хранилище (S3, CDN), сообщите полный адрес папки,
например `https://cdn.example.org/podcast/`. Сайт тогда пересоберём под этот адрес.
CORS для этого настраивать не нужно.

## 3. Как сервер должен отдавать файлы

Главное требование — **поддержка запросов по диапазону байтов (HTTP Range)**. Safari на iPhone
без ответа 206 может вообще не воспроизвести файл, в остальных браузерах не работает перемотка.

| Что | Как должно быть |
| --- | --- |
| Запрос с `Range: bytes=…` | Ответ `206 Partial Content` с заголовком `Content-Range` |
| `Accept-Ranges` | `bytes` |
| `Content-Length` | Есть, точный размер |
| `Content-Type` | `audio/mpeg` |
| Сжатие gzip/brotli | Для MP3 выключено: со сжатием сервер обычно перестаёт отвечать на Range |
| Авторизация | На этапе 1 нет, файлы открыты по прямой ссылке |
| Редиректы | Нет: файл отдаётся сразу по адресу, без перехода на другую страницу |
| `Cache-Control` | `public, max-age=31536000, immutable` |
| `X-Robots-Tag` | `noindex` (чтобы файлы не попадали в поиск) |
| HTTPS | Обязательно |

nginx и Apache отдают статические файлы с поддержкой Range по умолчанию. Обычно Range
ломают прокси, CDN со сжатием и отдача файла через PHP или другой скрипт.

**Если доступ к файлам всё же закроют авторизацией** (в этапе 2 так и будет): запрос с `Range`
от авторизованного пользователя должен получать тот же ответ 206, а не перенаправление
на страницу входа и не HTML с ошибкой. Плеер шлёт обычные запросы браузера, cookies своего
домена уходят с ними сами.

Пример для nginx:

```nginx
location /audio/ {
    alias /var/www/ne-pro-beg/audio/;
    types { audio/mpeg mp3; }
    gzip off;
    add_header Cache-Control "public, max-age=31536000, immutable";
    add_header X-Robots-Tag "noindex, nofollow" always;
}
```

## 4. Проверка

```sh
curl -sI -H "Range: bytes=0-1" https://<домен>/audio/01.mp3
```

Правильный ответ (размер файла будет свой):

```
HTTP/2 206
content-type: audio/mpeg
content-range: bytes 0-1/12144869
content-length: 2
accept-ranges: bytes
cache-control: public, max-age=31536000, immutable
x-robots-tag: noindex, nofollow
```

Ошибки:

- `HTTP/2 200` и `content-length` равен размеру всего файла — Range не поддерживается.
- `content-type: text/html` или `application/octet-stream` — неверный тип или вместо файла страница.
- `301` / `302` — редирект, его нужно убрать.

Проверить все 11 файлов сразу:

```sh
for n in 01 02 03 04 05 06 07 08 09 10 11; do
  printf '%s  ' "$n.mp3"
  curl -s -o /dev/null -w '%{http_code}  %{content_type}\n' -H "Range: bytes=0-1" "https://<домен>/audio/$n.mp3"
done
```

Везде должно быть `206  audio/mpeg`.

## 5. Что прислать обратно

Сайт показывает эпизод доступным, только когда знает его длительность. Её берём из самих
файлов. Запустите в папке с переименованными файлами (нужен ffprobe из пакета ffmpeg)
и пришлите вывод целиком:

```sh
for f in [0-9][0-9].mp3; do
  printf '%s\t%s\t%s\t%s\n' "$f" \
    "$(ffprobe -v error -show_entries format=duration -of csv=p=0 "$f")" \
    "$(wc -c < "$f" | tr -d ' ')" \
    "$(ffprobe -v error -show_entries format_tags=title -of csv=p=0 "$f")"
done
```

Получится 11 строк: имя, длительность в секундах, размер в байтах и название из тегов.
Например:

```
01.mp3	981.890589	12144869	Эпизод 1. Марафон и поэты
```

Ещё нужны адрес сайта (домен) и адрес папки с файлами, если она не `/audio/` на том же домене.
По этим данным соберём готовый сайт: папку статических файлов, которую нужно будет
положить в корень домена. Как её выложить, описано в `SERVER.md`.

## Замена файла позже

Файлы кэшируются в браузерах на год. Поэтому исправленный файл кладётся **под новым именем**
(`10-v2.mp3`), старый не перезаписывается. Новое имя и новый вывод команды из раздела 5
для этого файла нужно сообщить: сайт пересобирается под новое имя.
