# ТЗ для Claude Code: сайт-плеер подкаста «Не про бег»

Oct 25, 2026 · @Yuri Strofilov

Задание для Claude Code. Первый раздел описывает весь проект в двух этапах; остальные — первый этап, который делается сейчас: открытый сайт-плеер для партнёров проекта, без входа и без сервера.

## Общая схема проекта

Проект идёт в два этапа. Этап 1 — статический сайт для партнёров: тизер, плеер и 11 MP3 по прямым ссылкам. Этап 2 добавляет сервер со входом и проверкой премиум-подписки S10.run и закрывает файлы.

Сплошные рамки — этап 1, пунктир — этап 2. В обоих этапах плеер берёт звук напрямую из хранилища; во втором этапе ссылку на файл ему выдаёт сервер.

## Этап 1: открытый плеер для партнёров

Статический сайт без входа и без сервера. Аудитория — партнёры проекта. Задача этапа — работающий плеер и проверка фонового воспроизведения на их телефонах.

Входит:

- первая страница-тизер;
- плеер с одной кнопкой «Продолжить», который играет с погашенным экраном;
- список эпизодов;
- экран-подсказка для встроенных браузеров Telegram, Instagram и Facebook;
- установка на домашний экран как PWA (Progressive Web App, сайт с иконкой как у приложения);
- позиция прослушивания, сохранённая в телефоне;
- 11 MP3 в хранилище по прямым ссылкам;
- по желанию — общая RSS-лента (Really Simple Syndication, формат подписки подкаст-приложений).

Не входит: вход и аккаунты, проверка подписки S10.run, профиль, личные ленты, подписанные ссылки, сервер, база данных, прослушивание без сети, DRM (Digital Rights Management, шифрование контента).

Защита файлов от пересылки на этом этапе не нужна. От посторонних — только запрет индексации поисковиками (раздел «Хостинг и выкладка»).

## Правила кода, которые сохраняют путь ко второму этапу

Во втором этапе добавятся вход и проверка доступа. Чтобы не переписывать плеер, код первого этапа держит четыре точки замены.

1. **Ссылка на аудио — только через функцию `getAudioUrl(episode)`.** Этап 1: возвращает `audioBase + episode.file` из `episodes.json`. Этап 2: запрашивает у сервера подписанную ссылку. Интерфейс не знает, откуда ссылка. Плеер с первого дня обрабатывает ошибку загрузки: вызывает `getAudioUrl` заново и продолжает с `currentTime`, потому что во втором этапе ссылки будут истекать.
2. **Позиции — только через модуль `progressStore`** с методами `get(n)`, `set(n, seconds)`, `markDone(n)`, `all()`. Этап 1: `localStorage`. Этап 2: та же запись плюс синхронизация с сервером; при первом входе локальные позиции отправляются на сервер.
3. **Эпизоды — только из `episodes.json`.** В разметке ничего не захардкожено. RSS-лента собирается из того же файла. Поле `free` есть с первого дня, в этапе 1 не используется.
4. **Кнопки «Слушать» ведут на маршрут `#/play`.** Во втором этапе перед ним встанет проверка входа, ссылки в интерфейсе не меняются.

## Стек и структура репозитория

Vite и TypeScript без UI-фреймворка: приложение маленькое, а элементом `<audio>` проще управлять без лишнего слоя.

- Сборка — Vite, на выходе статические файлы.
- TypeScript в строгом режиме.
- Без React и Vue. Маршруты по hash: `#/` — тизер, `#/play` — плеер, `#/episodes` — список. Экран «откройте в браузере» — состояние, без маршрута.
- Шрифты Golos Text, Montserrat, Sofia Sans Extra Condensed лежат в репозитории (woff2, кириллица). Google Fonts не подключать: лишний сторонний запрос, а в ЕС встраивание Google Fonts уже приводило к судебным претензиям из-за передачи IP-адресов.
- Service Worker — минимальный, только для оболочки (раздел «Плеер»).
- Тесты: Vitest для `progressStore`, `getAudioUrl` и генератора ленты. Плеер проверяется руками на устройствах (раздел «Приёмка»).
- MP3 в репозиторий не кладутся: они лежат в хранилище.

## Данные: episodes.json

Всё содержимое подкаста — в одном файле; длительность и размер заполняет скрипт по самим MP3, руками их не вписывать.

```json
{
  "podcast": {
    "title": "Не про бег",
    "author": "Юрий Строфилов",
    "language": "ru",
    "artwork": "/cover-1024.jpg",
    "audioBase": "https://<хранилище>/audio/"
  },
  "episodes": [
    {
      "n": 10,
      "title": "Калоши",
      "file": "10.mp3",
      "durationSec": 4440,
      "bytes": 0,
      "chapters": [],
      "free": false
    }
  ]
}
```

| Поле | Смысл |
| --- | --- |
| `n` | Номер эпизода, 1–11 |
| `title` | Название; пока известно только у 10-го, остальные — `[Название эпизода N]` до ответа владельца |
| `file` | Имя файла в хранилище; при замене файла — новое имя (`10-v2.mp3`), чтобы не мешал кэш |
| `durationSec`, `bytes` | Заполняет `scripts/probe-audio.ts` через ffprobe |
| `chapters` | Главы книги внутри эпизода: `[{ "title": "Письма и калоши", "startSec": 0 }]`; пусто, пока нет тайм-кодов |
| `free` | Резерв для этапа 2 |

## Плеер

Один стандартный элемент `<audio>` с прямым MP3 — единственная схема, которая надёжно играет на iOS и Android с погашенным экраном.

**Воспроизведение**

- Один `<audio>` на всё приложение, создаётся один раз, `preload="metadata"`, без атрибута `crossorigin`.
- Запрещено: Web Audio, декодирование в JavaScript, HLS (HTTP Live Streaming) и MSE (Media Source Extensions). iOS останавливает такие схемы при блокировке экрана или ведёт себя с ними непредсказуемо.
- Переход к следующему эпизоду: по событию `ended` тот же элемент получает новый `src`, затем `play()`.
- Ошибка загрузки или сети: `getAudioUrl` заново, продолжение с `currentTime`. До трёх попыток с паузами 2, 5 и 10 секунд, потом сообщение и кнопка «Продолжить».
- После входящего звонка воспроизведение продолжается одним нажатием: браузеры сами его не возобновляют.

**Media Session** (системный интерфейс управления медиа)

- Метаданные: `title` — название эпизода, `artist` — «Юрий Строфилов», `album` — «Не про бег», обложка 512×512 и 1024×1024.
- Действия: `play`, `pause`, `seekbackward` (15 с), `seekforward` (30 с), `previoustrack` и `nexttrack` (соседний эпизод), `seekto`.
- `setPositionState` — при смене эпизода, скорости и после перемотки.
- Через Media Session плеером управляют экран блокировки, кнопки Bluetooth-наушников и часы Garmin и COROS.

**Позиция** (`progressStore`, `localStorage`)

- Запись каждые 10 секунд, на паузе и при уходе страницы в фон (`visibilitychange`, `pagehide`).
- Эпизод считается прослушанным, когда до конца остаётся меньше 30 секунд.
- При открытии — последний эпизод с сохранённой позиции минус 5 секунд, чтобы вспомнить контекст.

**Управление**

- Скорость 1×, 1,25×, 1,5× с сохранением тембра (`preservesPitch = true`), выбор запоминается.
- Перемотка −15 и +30 секунд.
- Звук включается только по нажатию: автостарт браузеры запрещают.

**Встроенные браузеры** (`env/inAppBrowser.ts`)

- Признаки Telegram, Instagram и Facebook (`FBAN`, `FBAV`) в строке User-Agent собраны в одном модуле. Реальные строки проверить на телефонах партнёров и дополнить: Telegram на iOS помечает себя не всегда.
- Во встроенном браузере вместо плеера — экран «Откройте в Safari / Chrome» с инструкцией и кнопкой копирования ссылки. На Android дополнительно — попытка открыть Chrome через `intent://`.

**Установка на домашний экран**

- `manifest.webmanifest`: `name` и `short_name` «Не про бег», `start_url` `/#/play`, `display` `standalone`, `background_color` и `theme_color` `#ED5E5A`, иконки 192, 512 и maskable; для iOS — `apple-touch-icon` 180.
- Предложение установить — после первого прослушивания: на iOS подсказка «Поделиться → На экран „Домой“», на Android — системный запрос (`beforeinstallprompt`).

**Service Worker**

- Кэширует только оболочку: HTML, CSS, JavaScript, шрифты, иконки.
- Запросы к MP3 не перехватывает вообще. Перехват запросов на загрузку частями ломает перемотку в Safari.

## Аудиофайлы

Целевой формат — MP3 64 кбит/с моно с постоянным битрейтом и громкостью −16 LUFS; пережимать ли исходники, владелец решает на слух.

| Параметр | Значение |
| --- | --- |
| Формат | MP3, CBR (Constant Bit Rate, постоянный битрейт): с переменным битрейтом браузеры неточно перематывают |
| Битрейт и каналы | 64 кбит/с, моно; около 28 МБ на час |
| Частота | 44,1 кГц |
| Громкость | −16 LUFS (Loudness Units relative to Full Scale, единица воспринимаемой громкости), интегральная |
| Пик | Не выше −1 dBTP (decibels True Peak, истинный пик) |
| Теги | ID3 v2.3 (служебные теги MP3): название, номер, автор, обложка; главы — CHAP/CTOC, когда будут тайм-коды |
| Имена | `01.mp3` … `11.mp3` |

- Несжатых исходников нет, поэтому пережатие MP3 в MP3 добавит потерь. Сравнить на одном фрагменте текущий файл и вариант 64 кбит/с моно, решить до загрузки.
- Если файлы не пережимаются, громкость поправляется без пережатия: mp3gain меняет усиление кадров шагами по 1,5 дБ.
- Команды ffmpeg и ffprobe для этих шагов Claude Code пишет в `scripts/` и показывает владельцу до запуска.

## Общая RSS-лента (по желанию)

Один статический XML-файл для партнёров, которым удобнее слушать в подкаст-приложении; во втором этапе он удаляется.

- Собирается `scripts/build-feed.ts` из `episodes.json` при каждой сборке.
- Адрес трудно угадать: `/feed-<16 случайных символов>.xml`. На сайте ссылка не публикуется, владелец рассылает её партнёрам сам.
- Канал: `itunes:block` = `yes` (не попадать в каталоги), `itunes:type` = `serial` (выпуски по порядку с первого), язык `ru`, автор, обложка 3000×3000.
- Выпуск: `itunes:episode` 1–11; `enclosure` с адресом файла, типом `audio/mpeg` и размером в байтах; `itunes:duration`; постоянный `guid` (`ne-pro-beg-ep-10`); даты публикации по возрастанию номера.
- Spotify частные ленты не принимает. Подходят Apple Podcasts, Overcast, Pocket Casts, AntennaPod и Podcast Addict.

## Хостинг и выкладка

Сайт — на любом статическом хостинге с HTTPS, MP3 — в объектном хранилище с открытым чтением; провайдера выбирает владелец (открытые вопросы).

- HTTPS обязателен: без защищённого соединения не работают Service Worker и установка на домашний экран.
- Хранилище обязано поддерживать запросы на загрузку частями (Range): ответ `206 Partial Content`, заголовки `Accept-Ranges: bytes`, `Content-Length`, `Content-Type: audio/mpeg`. Без этого не работает перемотка. Проверить командой `curl -I -H "Range: bytes=0-1" <адрес файла>` до подключения к плееру.
- Кэш файлов: `Cache-Control: public, max-age=31536000, immutable`; при замене файла — новое имя.
- Запрет индексации: `<meta name="robots" content="noindex">` на всех страницах, `robots.txt` с `Disallow: /`, заголовок `X-Robots-Tag: noindex` в хранилище, если провайдер позволяет.
- Сайт и хранилище должны открываться из стран, где находятся партнёры. Проверить до рассылки ссылки.
- Выкладка одной командой `npm run deploy`, описанной в README. Ключи доступа к хостингу — только в переменных окружения, не в репозитории.

## Этап 2: что добавится

Во втором этапе появляются сервер, вход и проверка подписки S10.run; плеер, дизайн и файлы первого этапа остаются, меняется только содержимое точек замены. Подробное ТЗ на этап 2 — отдельно, здесь границы, которые нельзя закрыть в этапе 1.

- **Вход:** email и шестизначный код из письма (10 минут, 5 попыток, не чаще одного письма в минуту). Ссылки для входа из письма не использовать: на iOS установленный сайт хранит cookies отдельно от Safari. Сессия 180 дней.
- **Проверка подписки** — запрос с сервера сайта на сервер S10.run:

```
GET /premium-status?email=<email>
Authorization: Bearer <секретный ключ сайта>

→ true | false
```

- Ответ кэшируется на 30 минут. Если S10.run недоступен, берётся последний известный статус не старше 24 часов.
- **Таблица доступа** для других оснований: покупка, подарочный код, ручная выдача. Признак `free` у эпизодов открывает их без подписки.
- **Файлы** переезжают в закрытое хранилище. `getAudioUrl` получает от сервера подписанную ссылку со сроком 6 часов. Старые прямые ссылки и общая лента удаляются.
- **Личные RSS-ленты** с ключом в адресе. Ссылки на выпуски — постоянные; сервер проверяет ключ и отвечает перенаправлением 302 на подписанную ссылку. Кнопки «Добавить в Apple Podcasts / Overcast / Pocket Casts», сброс ключа.
- **Позиции на сервере.** При первом входе `progressStore` отправляет локальные позиции на сервер.
- **Экраны:** вход (email, код), «нет доступа», профиль — уже на холсте.
- **Персональные данные:** GDPR (General Data Protection Regulation, европейский регламент о защите данных) и, для граждан России, требования локализации по 152-ФЗ.
